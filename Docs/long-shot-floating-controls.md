# 长截图右侧固定按钮重复

2026-11-12

用户提供的长图右侧反复出现圆角/蓝字残片，并确认这是聊天页面自带的悬浮按钮。该按钮固定在视口内，正文则随滚动移动。

原拼接器只保留累计图片、追加新帧底部条带（同时处理整行固定底栏）。局部悬浮按钮不占满整行，因此可以不影响位移估计，却随每段尾条进入结果。匹配阶段忽略部分边缘也不等于从最终图片排除这些控件。

## 复现

使用960×560视口的确定性聊天正文，右下角加入72×40的固定按钮。两种背景分别为右侧空白与真实文字，连续滚动137像素；另有每次360像素的大步幅场景。

修复前3项测试共8处失败：滚动位移、置信度、结果尺寸、左侧正文和后续帧确实提供干净像素的断言均通过，失败只集中在旧按钮覆盖区域（每处约3000像素不同）。这区分了“位移错误”和“遮挡重复进入条带”。

## 修复方法

在已经验证的滚动重叠区选择一条水平接缝：接缝上方沿用旧图，下方使用新帧的完整尾部。对滚动对齐后仍不同的区域，结合其在原视口位置是否静止来决定应优先使用哪一帧；没有这类差异时选重叠区中部。

接缝代价区分旧、新浮层：保留旧按钮的代价推动接缝向上，新帧顶部固定元素的代价推动接缝向下。只一侧在视口原位置稳定时，纯色底也可作为遮挡证据；两侧都稳定时用局部纹理区分按钮与空白。低对比边缘及两行抗锯齿余量避免只去掉蓝字、留下浅框。

所有输出仍直接复制输入帧的原始像素，不进行文字重绘、涂白、生成式修补或整列裁剪。固定头尾和结果尺寸保持原约定，下一次位移估计仍使用完整原始帧。

## 边界

后续帧必须真正露出此前被遮挡的内容，才能恢复。最后一帧仍被按钮遮住的位置允许保留原按钮一次。半透明动画、多个相互冲突的遮挡或没有重叠内容的快滚，不保证能选出无瑕疵的接缝；本次不是通用界面控件识别或任意区域修补。

用户给的是已合成图片，缺少其原始连续帧；自动回归复现了同类机制，安装版在原聊天页面的实际效果需要重新截取确认。
